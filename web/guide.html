PUNE TEAM USER GUIDE

Your first AMR experiment,
from file to evidence.

Start here if you have never trained a model. This guide explains what to enter, what to check, and what the results mean.

PracticePrepare dataRun an experimentPredict an isolateAdd new dataLocal PythonTroubleshooting
What this tool can establishIt estimates resistance to one selected antibiotic from measured results for other antibiotics. It is a research model, not a laboratory susceptibility test or prescribing tool. Public-source results do not establish performance in your laboratory or clinical validation. Training until one test set looks perfect would invalidate that test.

1. Practice without patient data

  1. Open the workspace on a desktop Chrome, Edge or Firefox browser. Keep a stable internet connection for the first run.
  2. Select Start the guided demo. It loads synthetic practice data and automatically checks, trains and tests the model.
  3. The first operation prepares the analysis engine. It downloads the browser-based Python runtime and scientific packages (about 100 MB); this can take several minutes depending on your connection. The operation panel names the current stage. Later visits may reuse the browser cache.
  4. The demo continues from the data check into training and evaluation on a held-out synthetic source. Review the plain-language result explanation and the full metrics. Synthetic performance verifies software behavior only.
  5. Go to Test an isolate, enter a measured example panel, and run the research prediction.
  6. Use Save my experiment for a ZIP and browser-generated PDF, or download the HTML report separately. The workflow, selected CSV/workbook, last result and downloadable experiment can be saved in this browser. Resume can show the saved result and ZIP; rerun the analysis before making new predictions.

Each session runs on this device. There is no account, shared model, cloud backup or patient-data server. Resume restores the saved setup, CSV and last saved result when available; a restored result does not make a model ready for new predictions. The browser uses Random Forest in the broad framework; native Python can run actual XGBoost. These are separate experiments.

2. Prepare a real laboratory file

Ask the data steward for authorized, de-identified laboratory observations. Use coded isolate and patient identifiers so duplicates can be grouped. Do not put names, telephone numbers or addresses in a file. Keep the code-to-person mapping outside this project.

Download the MIC template, categorical AST template, or synthetic example file for practice only. Do not use synthetic example rows as biological evidence. The browser accepts CSV and Excel (.xlsx), in long format (one isolate–antibiotic result per row) or wide format (one antibiotic per column). It prepares a separate long-format analysis copy after you review the mapping. Only the first worksheet of an Excel workbook is read. Files stay in this browser; they are not uploaded. See the data dictionary.

MIC and categorical AST are different formats. If your lab has only S/I/R, choose categorical AST. Do not turn categories into invented MIC values. Preserve ≤ and ≥ censoring. Do not multiply results to compensate for another laboratory's dilution series. Strict comparison needs documented methods, QC, lab identity and a reviewed standard/version.

Training requires measured target-antibiotic outcomes as labels and other antibiotics as predictors. The target and its combinations are excluded from predictors. For a new isolate, you enter the other-drug panel; the target outcome is not an input. Gene calls are annotations, not automatic resistance labels.

3. Audit, train and review

  1. Select Use my own data, then choose your CSV or .xlsx workbook (browser limit: 10 MB). Confirm the detected long/wide layout, inspect suggested column matches and the prepared preview, and choose the documented source type. Blank measurements remain blank. The original file is preserved; larger files use local Python.
  2. In Choose what you want to predict, select a target with enough recorded resistant and susceptible examples. Preliminary counts are based on distinct isolates; the complete data check may exclude records. Choose whether the recipe should prioritize catching resistance or reducing false alarms. Then open Advanced research settings only if your modeling lead asks you to set a validation design or comparability policy. Choose the original interpretation standard and enter its documented version; these fields filter evidence and do not recalculate historical lab labels.
  3. Review Laboratory comparability. Exploratory mode exposes provenance gaps. Strict mode requires actual lab, method, QC and pinned-version documentation; missing evidence can exclude data. The modeling lead should review this choice.
  4. Choose the split before seeing results. Internal grouped evaluation is a practice/development design. Source or laboratory holdout needs the exact IDs found by the audit. A public PRJNA study ID is not a local laboratory ID.
  5. Click Check my data. The status card says Ready, Needs attention or Cannot run, and lists exclusions, provenance gaps and patient linkage. Mark each item reviewed after checking the source record. An exclusion is information to review, not permission to fabricate a field.
  6. When the configuration and source are reviewed, click Train & test. Follow the named Check, Train and Test on unseen isolates stages. If a run fails, read the error and restart the analysis after addressing the stated issue. The runtime selects predictors and thresholds from development data and evaluates the held-out partition.
  7. Start with the result summary, then the evidence badge and key counts. Open Full detail for confidence intervals, confusion matrix, source/species breakdowns and model information. Read missed resistance and false alarms before AUROC. A failed target stays visible, and a blocked run means data or design is insufficient.
  8. Choose Save my experiment to download the reproducible ZIP and open the browser Print dialog; choose “Save as PDF” for the report. You can also download the HTML report. The experiment is autosaved on this device when browser storage allows it, and the Home screen offers Resume and Clear saved work. A restored result can be reviewed and downloaded, but rerun before making a new prediction. Export the complete experiment ZIP. To inspect performance across sources, select Validate all sources and save that separate bundle; this replaces the session model.

What the numbers mean

False negative (missed resistance)
A resistant test isolate predicted non-resistant. For AMR this is a critical failure to examine.
False positive (false alarm)
A susceptible test isolate predicted resistant.
Sensitivity
The fraction of resistant test isolates detected. A development sensitivity goal of 1.0 is a target, not a guarantee.
Specificity
The fraction of susceptible test isolates correctly predicted non-resistant.
AUROC and uncertainty
AUROC measures ranking across thresholds. It does not guarantee the chosen threshold works. Read exact and cluster confidence intervals; small cohorts give uncertain estimates.

The current native public-source result is 3 FN / 7 FP among 165 test isolates (29 R / 136 S). The browser result is 15 FN / 4 FP on that source. Neither result represents validation for your laboratory. Inspect the method and archived results.

4. Enter a new isolate correctly

  1. Train a model in this session first. Pick a supported species from the dropdown.
  2. Copy the measured panel from the laboratory report, using the trained format and standard/version. Do not enter the target antibiotic as a predictor.
  3. For a MIC result “≤ 0.5 mg/L”, choose <= and type 0.5. For “> 16 mg/L”, choose > and type 16. These are input-format examples, not example patients.
  4. For categorical AST, select the reported S, I, R or SDD value. Do not treat I as S by hand. Endpoint handling is recorded in the run.
  5. Leave untested drugs missing. Zero is not a missing measurement. Meet the run's minimum measured panel; unsupported panels are rejected.
  6. Select Run research prediction. Read the estimated probability, research decision, evidence status and operating-point status together.

A 70% estimate is a model output; it is not proof of a 70% clinical risk. Calibration and transportability must be evaluated. “Research non-resistant” does not establish safe susceptibility. Strict provenance models and combination MIC panels require the native external CSV workflow because this compact form cannot verify per-observation provenance or inhibitor concentration.

Changing source, target or model settings invalidates the session model. Audit and retrain before another prediction.

5. Add data without changing the architecture

Keep the same observation schema. New antibiotics, species or endpoint choices belong in reviewed configuration files, not duplicated model code.

  1. Separate a new development batch from a fresh independent evaluation cohort. Keep the independent cohort outside merging and retraining.
  2. In the workspace, select your new CSV, open Add data to an existing observations file, and optionally select the earlier observations CSV.
  3. Click Prepare checked batch. It removes exact duplicate rows and rejects differing rows with the same source/isolate/drug identity. It also rejects inconsistent lab identities within an isolate. Resolve retests with the lab; do not overwrite an inconvenient outcome.
  4. Save the combined CSV and batch manifest. The next audit uses that combined CSV. Preparation does not establish scientific validity.
  5. Audit under a reviewed configuration, train a new experiment, and compare development evidence. Every run gets its own output directory and recorded input hash.
  6. Use fresh external data to evaluate the chosen run once. The previous public challenges are already inspected retrospective evidence. They cannot become new independent validation by running them again.
  7. Record failures and collect the missing measurements or missing susceptible/resistant groups. Stop if evidence is insufficient. Never tune until a repeatedly inspected test set reaches 100%.

Measured AST remains the truth source. This workflow checks structure, provenance and reported evidence; it cannot repair incorrect laboratory measurements or ensure perfect predictions. A future local cohort should include both resistant and susceptible isolates, patient grouping and laboratory metadata.

6. Run on a local computer

The browser is the simplest starting point. Use local Python for large cohorts, actual XGBoost, or strict external evaluation. Obtain the source ZIP or clone the repository, and open a terminal inside its extracted folder. Install Python 3.12 and Node 20+ from their official sites.

Windows PowerShell

py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-local.lock.txt
.\.venv\Scripts\python.exe -m pip install -e . --no-deps
.\.venv\Scripts\python.exe -m amr_discovery --help

macOS / Linux

python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-local.lock.txt
.venv/bin/python -m pip install -e . --no-deps
.venv/bin/python -m amr_discovery --help

In the commands below, python means your virtual environment's executable above. Put private input and output files under data/private/, which is excluded from Git and the website download. Replace example paths with your actual files. Create a reviewed JSON by copying configs/framework_native.json, setting the actual standard/version, format, target and split. For the reserved AST workbook workflow, install the optional XLSX reader with python -m pip install openpyxl, then import the workbook into a new private folder with python -m amr_discovery import-asts-workbook --data "your-file.xlsx" --out data/private/asts-001. Choose one of configs/reserved_ast_meropenem.json, reserved_ast_imipenem.json, reserved_ast_colistin.json or reserved_ast_ceftazidime_avibactam.json; use that config for both audit and run. These configs use seven prespecified non-reserved predictors, the supported E. coli and K. pneumoniae species, isolate-grouped 70/30 evaluation, and one reserved drug as the held-out target. A predictor absent from the workbook is omitted using training data only. If the target has no measured outcomes, the run is blocked. For a first local experiment choose {"mode":"internal"}; a public-study holdout ID cannot be used for your own cohort.

python -m amr_discovery prepare-batch --base data/private/earlier.csv --data data/private/new.csv --out data/private/batch-002
python -m amr_discovery audit --data data/private/batch-002/observations.csv --config data/private/reviewed.json --out data/private/audit-002
python -m amr_discovery run --data data/private/batch-002/observations.csv --config data/private/reviewed.json --out data/private/run-002
python -m amr_discovery external --run data/private/run-002 --data data/private/fresh-independent.csv --out data/private/external-002

Each output path must be new. Open report.html after audit/training and read the saved JSON, predictions and split manifest. external creates a reproducible snapshot automatically and rejects overlap with development data. It does not refit. Do not load untrusted joblib model files.

npm ci --ignore-scripts

When something does not work

Error: “Missing columns: drug, evidence_class, isolate_id, measurement, method, operator, reported_sir, source_id, species, standard, standard_version, units”

This means the analysis engine received a file that has not been converted to the required long-format observation table. It often happens when the source is a wide matrix with one antibiotic per column. It is an import/schema issue, not a model-training failure.

  1. Return to Use my own data and choose the original file again.
  2. Inspect the detected layout, edit the column mappings, and select each antibiotic result column. Confirm the preview shows one row per isolate–drug observation before running Check my data.
  3. Map isolate ID, source/study ID, species, measurement or reported S/I/R/SDD result, method, units, standard/version and evidence class only from the source documentation. If a value is unknown, leave it unknown; do not guess.
  4. If the browser cannot normalize this workbook, use the local Python import-wide workflow described below. It requires an explicit reviewed mapping file.

Important: a categorical AST matrix is not an MIC matrix. Do not convert S/I/R into numeric MIC values. The import should preserve missing measurements and source values.

My columns are not recognized or no isolates are eligible

Review the suggested mapping and correct each field using the original lab record. For Excel, only the first worksheet is read; date serials may need conversion to ISO dates before importing. Check species, drug names, host, method, standard/version, target labels and minimum panel. Read exclusions. A header-only template has no observations.

How do I use each feature?

Build an experiment: select the dataset, target antibiotic, endpoint and predictor panel; then review the data audit before training.

Data check: inspect exclusions, class counts, source/laboratory provenance and repeated-isolate grouping. Fix the source record rather than bypassing an exclusion.

Train and test: run only after the data and split are reviewed. Read false negatives and false positives, confidence intervals and source-wise results before AUROC.

Test an isolate: requires a successfully trained session model. Enter only measured predictor drugs; leave untested drugs missing and never enter the target antibiotic as a predictor.

Topology: gene and geography networks are exploratory summaries of development data, not causal interactions or transmission evidence.

Save/export: download the experiment ZIP and report before closing the tab. Files and session models remain in this browser.

Too few susceptible or resistant samples

Collect the missing class with documented sampling. Do not duplicate rows, change labels, relax gates just to train, or invent measurements. The supplied Indian study currently has too few susceptible isolates for its configured validation.

Conflicting rows while adding a batch

The same source/isolate/drug has different observations or metadata. Ask the laboratory to resolve retests and identity. Keep original evidence; correct the reviewed file before merging. The application does not choose the convenient result.

Runtime download failed or the browser is slow

Check network access to jsDelivr, retry on a desktop browser, close other memory-heavy tabs, or use local Python. Use Stop if needed; it discards the fitted session model. No GPU or paid service is required.

Prediction is disabled or a strict prediction is rejected

Train successfully in this tab first. A settings change clears readiness. For a strict model use external CSV evaluation with laboratory metadata. A validation suite produces reports rather than a session prediction model.

I closed the tab before saving

If browser storage was available, the setup and chosen CSV may be available from Resume where you left off. A saved result and ZIP may be restored from this browser. Rerun the analysis before making a new prediction, and download the ZIP/report for a portable copy. You can clear the saved workflow from the Home screen.

Hand off to the next teammate

Share the reviewed configuration, batch manifest and authorized experiment artifacts through your institution's approved channel. Record target, format, standard/version, input hash, development data and test design. Clinical lead reviews the endpoint; data steward reviews provenance; modeling lead trains; an independent evaluator reviews the fresh cohort. Never publish private records in the public repository.
